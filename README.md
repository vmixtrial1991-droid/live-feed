# Живая лента 5.1.1

Веб-приложение для мероприятий: гости по QR-коду вводят имя и отправляют текст или фото —
всё сразу появляется на витрине и на полноэкранном показе. Модерации нет: сообщение уходит
в эфир в момент отправки. Есть встроенный квиз для зала на той же платформе.

Событий на одном сервере может быть сколько угодно. Каждое заводится в админке и получает
свои ссылки и QR-коды: для ведущего (по паролю), для экрана (без пароля), для гостей
(с кодом приглашения) и для игры-квиза. События изолированы — свои ссылки, своя база,
свои фото, — и удаляются без хвостов: папка `data/events/АДРЕС` целиком.

Стек: Python + FastAPI + SQLite, без Node.

## Что нового в 5.1.1

- **Картинка вопроса больше не мелькает от прошлого кадра.** При переходе на
  следующий вопрос браузер держал на экране прежний снимок, пока не загрузит
  новый: зал видел фотографию от предыдущего вопроса под текстом следующего.
  Тем дольше, чем медленнее сеть. Теперь новый снимок появляется только после
  загрузки, а до этого на его месте пустое место правильного размера.

## Что нового в 5.1

- **Экран квиза свёрстан по ТЗ**: виртуальный холст 1920×1080, три схемы кадра
  (текст, широкое фото сверху, высокое фото сбоку), карточки ответов в `em`,
  подгонка кегля под кадр и рост шрифта, когда места много. Проверено на 16:9,
  16:10, 5:3 и 3:4.
- **Пределы длины текста** (раздел 12 ТЗ): два уровня — рекомендуемый и жёсткий,
  отдельно для вопроса и для вариантов, с учётом того, есть ли картинка и сколько
  вариантов. Таблица одна на сервер, панель ведущего и стенд проверки.
- **Три ответа встают «2 + 1»** во всех схемах, кроме C. Если слово шире половины
  группы — колонка, чтобы слово не рвалось.
- **Таблица лидеров — отдельная сцена** со своей вёрсткой: равный счёт даёт равное
  место, промежуточная листает зал пачками по 10, финальная показывает первую
  десятку и держится.
- **Лента использует всю ширину сэйфзоны**: подпись больше не ограничена 22 знаками.
  Раньше длинный текст ломался на четыре узкие строки, хотя по краям оставалась
  половина кадра. Кегль подбирается по фактической высоте содержимого, с потолком
  по самому длинному слову.
- **Слайдшоу переключает кадры так же плавно, как лента** — раньше снимок
  подменялся одним кадром, без перехода.

## Что нового в 5.0

- **Квиз на той же платформе**: у события появляется четвёртая ссылка и отдельный QR —
  страница игры `/e/АДРЕС/quiz`. Кто уже отправлял в ленту, попадает в игру сам,
  вторичный вход не нужен: тот же код приглашения, тот же билет.
- **Ведущий ведёт игру из кабинета**, вкладка «Квиз»: сам сочиняет вопросы (2–4 варианта,
  любой можно копировать кнопкой ⧉). Игра начинается кнопкой «Запустить квиз»: экран
  плавно перекрывается тёмным градиентом, на нём название события и QR игры — зал
  подключается со своих телефонов, а вопросы к этому моменту ещё можно дописывать.
  Название игры своё, отдельно от названия события: ведущий задаёт его на вкладке «Квиз»,
  и оно стоит на стартовом экране крупно над QR.
  Дальше вся цепочка — одной шаговой кнопкой: «Открыть первый вопрос → Закрыть приём →
  Показать ответ → Дальше», перепутать направление нельзя. Экран тот же — на время игры
  лента встаёт, вместо неё название с QR, вопрос, распределение ответов и таблица
  лидеров. Лидеры посреди игры — пауза: шаг с таблицы возвращает к тому же вопросу и
  той же стадии, с тем же остатком отсчёта.
- **Время на ответ** — у каждого вопроса своё; крупный отсчёт висит только на проекторе,
  телефоны никто не торопит, приём закрывает ведущий, а не секундомер.
- **Картинка к вопросу** — необязательная: сервер сам пережимает её до 1600 px,
  как фото ленты. На проекторе фото слева, вопрос и ответы справа, ответы сеткой
  2×2; с картинкой вопрос короче (до 90 знаков), варианты — до 40. На телефоне
  фото нет: там вопрос и кнопки, а смотреть зал будет на большом экране.
- **Хитрые вопросы без очков** — опрос о том, как думает зал; правильный не подсвечивается.
- **Подсмотреть ответ нельзя**: правильный не уходит зрителям до стадии «Показать ответ»,
  распределение — не раньше закрытия приёма, а чужие ответы не видны никому, кроме
  самого отвечающего. Полосы «кто куда ответил» видит только ведущий.
- **Таблица лидеров с местами**: равный счёт даёт равное место; промежуточная таблица
  листает весь зал пачками, финальная показывает первую десятку и держится на экране.
- **Имя участника правится прямо в игре**; старые сообщения остаются под прежним именем.

## Что нового в 4.1.1

- **Экран не слепнет от собственной защиты**: CSP из 4.1 глушила скрипт самой страницы,
  и экран показывал пустоту. Починено, а ссылки на экран в кабинетах работают как прежде.
- **F5 на проекторе не рвёт показ**: экран запоминает свой ключ на 24 часа, полная
  ссылка с `?d=` нужна только при первом открытии.
- **Витрина в кабинетах снова в эфире**: её канал подключается с ключом экрана.

## Что нового в 4.1

- **Билеты доступа**: гость один раз вводит код — и дальше ходит по событию со своим
  билетом (8 часов); ведущий — 12, экран — 24. Закрытым оказался весь внутренний API.
- **Ссылка экрана с ключом `?d=`**: экран, его канал, QR-код приглашения и фотографии
  больше не открываются всякому, кто знает адрес события. Ключ у события один и не меняется.
- **Фото по коротким подписанным ссылкам** (живут 10 минут) и миниатюры для сетки в кабинете.
- **Дельты вместо полных снимков** в канале экрана: слабая сеть больше не рвётся от
  JSON со всеми фото вечера на каждое новое сообщение.

## Что нового в 4.0

- **Вкладка «Слайдшоу»** в кабинете ведущего: галочка у фотографии в ленте переносит её
  в галерею, отдельной кнопкой галерея выходит на экран. У слайдшоу своя пауза,
  она не трогает ленту.
- **Архив фотографий отделён от ленты**: удаление сообщения убирает строку, но не стирает
  файл; галерея живёт своей жизнью.
- **Правка текста** — своё окно со счётчиком символов, правка видна на экране сразу.
- **Код приглашения вводится руками** и без учёта регистра.

## Установка

### Docker (рекомендуется)

```bash
git clone https://github.com/vmixtrial1991-droid/live-feed.git live-feed
cd live-feed
cp .env.example .env    # вписать ADMIN_PASSWORD
docker compose up -d
```

Админка — `/admin`, пароль из `.env`. Сертификат Let's Encrypt выпускается сам,
если в `.env` прописан `DOMAIN`; без него сайт работает по http.

### Ubuntu/Debian без Docker

```bash
sudo bash deploy/remote-ip.sh          # по IP, http
sudo bash deploy/remote.sh домен.ru    # с сертификатом Let's Encrypt
```

Скрипты ставят nginx, окружение и systemd-сервис; пароль печатается в конце
и лежит в `/etc/live-feed.env`. Повторный запуск безопасен.

### Локально

```bash
python -m pip install -r requirements.txt
python run.py
```

Адрес админки и пароль администратора печатаются в консоли при старте.

## Где подробности

- `DEPLOY.md` — пошаговое развёртывание на сервер, в том числе без интернета
- `CONTEXT.md` — как устроен проект, на какие грабли наступали
- `LAYOUT.md` — вёрстка экрана квиза: схемы кадра, карточки, пределы текста
- `.github/workflows/tests.yml` — CI: тесты на Python 3.11 и 3.12, shellcheck, сборка образа

Текущая версия — **5.1.1**, она развёрнута на сервере. Ветка `main` — рабочая:
новые версии на прод не едут без отдельного решения.
