# Живая лента 5.0

Веб-приложение для мероприятий: гости по QR-коду вводят имя и отправляют текст или фото —
всё сразу появляется на витрине и на полноэкранном показе. Модерации нет: сообщение уходит
в эфир в момент отправки.

Событий на одном сервере может быть сколько угодно. Каждое заводится в админке и получает
свои три ссылки и QR-код: для ведущего (по паролю), для экрана (без пароля) и для гостей
(с кодом приглашения); с 5.0 у события есть ещё адрес и QR игры-квиза. События изолированы — свои ссылки, своя база, свои фото, — и удаляются
без хвостов: папка `data/events/АДРЕС` целиком.

Стек: Python + FastAPI + SQLite, без Node.

## Что нового в 5.0

- **Квиз на той же платформе**: у события появляется четвёртая ссылка и отдельный QR —
  страница игры `/e/АДРЕС/quiz`. Кто уже отправлял в ленту, попадает в игру сам,
  вторичный вход не нужен: тот же код приглашения, тот же билет.
- **Ведущий ведёт игру из кабинета**, вкладка «Квиз»: сам сочиняет вопросы (2–6 вариантов),
  открывает, закрывает и переключает прямо на событии. Экран тот же — на время игры
  лента встаёт, вместо неё вопрос, распределение ответов и таблица лидеров.
- **Хитрые вопросы без очков** — опрос о том, как думает зал; правильный не подсвечивается.
- **Подсмотреть ответ нельзя**: правильный не уходит зрителям до закрытия вопроса,
  а чужие ответы не видны никому, кроме самого отвечающего.
- **Имя участника правится прямо в игре**; старые сообщения остаются под прежним именем.

## Что нового в 4.1.1

- **Экран не слепнет от собственной защиты**: CSP из 4.1 глушила скрипт самой страницы,
  и экран показывал пустоту. Починено, а ссылки на экран в кабинетах работают как прежде.
- **F5 на проекторе не рвёт показ**: экран запоминает свой ключ на 24 часа, полная
  ссылка с `?d=` нужна только при первом открытии.
- **Витрина в кабинетах снова в эфире**: её канал подключается с ключом экрана.

## Что нового в 4.1

- **Билеты доступа**: гость один раз вводит код — и дальше ходит по событию со своим
  билетом (8 часов); ведущий — 12, экран — 24. Закрытым оказался весь внутренний API.
- **Ссылка экрана с ключом `?d=`**: экран, его канал, QR-код приглашения и фотографии
  больше не открываются всякому, кто знает адрес события. Ключ у события один и не меняется.
- **Фото по коротким подписанным ссылкам** (живут 10 минут) и миниатюры для сетки в кабинете.
- **Дельты вместо полных снимков** в канале экрана: слабая сеть больше не рвётся от
  JSON со всеми фото вечера на каждое новое сообщение.

## Что нового в 4.0

- **Вкладка «Слайдшоу»** в кабинете ведущего: галочка у фотографии в ленте переносит её
  в галерею, отдельной кнопкой галерея выходит на экран. У слайдшоу своя пауза,
  она не трогает ленту.
- **Архив фотографий отделён от ленты**: удаление сообщения убирает строку, но не стирает
  файл; галерея живёт своей жизнью.
- **Правка текста** — своё окно со счётчиком символов, правка видна на экране сразу.
- **Код приглашения вводится руками** и без учёта регистра.

## Установка

### Docker (рекомендуется)

```bash
git clone https://github.com/vmixtrial1991-droid/live-feed.git live-feed
cd live-feed
cp .env.example .env    # вписать ADMIN_PASSWORD
docker compose up -d
```

Админка — `/admin`, пароль из `.env`. Сертификат Let's Encrypt выпускается сам,
если в `.env` прописан `DOMAIN`; без него сайт работает по http.

### Ubuntu/Debian без Docker

```bash
sudo bash deploy/remote-ip.sh          # по IP, http
sudo bash deploy/remote.sh домен.ru    # с сертификатом Let's Encrypt
```

Скрипты ставят nginx, окружение и systemd-сервис; пароль печатается в конце
и лежит в `/etc/live-feed.env`. Повторный запуск безопасен.

### Локально

```bash
python -m pip install -r requirements.txt
python run.py
```

Адрес админки и пароль администратора печатаются в консоли при старте.
